# Software Architecture Description

**SE in Practice · Gran Sasso Science Institute**  
**Francesco Basciani**

This interactive lesson explores a central software engineering idea:

> **Requirements determine what a system must achieve; architectural design determines how the system is organized to achieve it.**

The lesson moves across two safety-critical domains, **space systems** and **railway systems**, before focusing on a collaborative case study: the design of a **Train Station Simulator**.

::::{grid} 1 1 2 2
:::{card} Learning objective
Connect functional and non-functional requirements to architectural drivers, components, responsibilities, and interactions.
:::
:::{card} Classroom format
Short instructor-led sections are followed by a group activity in which students discuss requirements and sketch an abstract architecture on paper or a whiteboard.
:::
::::

## Lesson flow

1. **Requirements shape architecture** - a reusable design process across domains.
2. **Space example** - autonomy and adaptivity in satellites.
3. **Railway domain** - safety, security, reliability, efficiency, and station entities.
4. **Train Station Simulator** - the problem statement.
5. **Group activity** - derive requirements and an abstract architecture.
6. **Debrief** - compare the group solutions with a possible set of requirements and architecture.

:::{important} How to use this book in class
This site is designed to be **projected by the instructor**. Students may also open the same URL on their own devices, but the main design activity remains collaborative and physical: discussion, paper, and whiteboard sketches. Interactive elements are used mainly to reveal information progressively and support the final discussion.
:::
